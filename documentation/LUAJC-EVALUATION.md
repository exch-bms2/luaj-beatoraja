# LuaJCの評価（保留）

2026-11-25。インタプリタのループ（JFRで描画スレッドのJava CPUの42〜56%）を取り除く手段として、LuaJC（LuaをJVMのバイトコードに変換する機能）を評価した。
**スキンで使うと、エラーを出さずに誤った結果を返すことが分かったため、保留にした。** コードは元に戻してある。

パッチ：
- luaj側の修正と `LuaJC.loadVerified`：[changes/luajc-trial-luaj.patch](changes/luajc-trial-luaj.patch)
- beatoraja側のオプトインのフラグ `-Pluajc=true` / `-PbcelJar`、`SkinLuaCompiler`、`SkinLuaCompilerTest`：[changes/luajc-trial-beatoraja.patch](changes/luajc-trial-beatoraja.patch)（beatorajaリポジトリで適用する）

## 速度（スキンに似た処理、各3回、masterのjar）

| 処理 | インタプリタ | LuaJC |
| --- | ---: | ---: |
| draw条件（sidemenu.lua:725相当） | 289〜357 ns | 173〜177 ns |
| Luaの関数への末尾呼び出し | 165〜200 ns | 70〜76 ns |
| テーブルの数値の読み取り | 727〜783 ns | 167 ns |
| 別チャンクのフィールド参照 | 122〜159 ns | 71〜74 ns |

45〜78%速く、回ごとのばらつきも小さい。

## コスト

- **読み込み時間**：小さなチャンク3000個で、インタプリタは1チャンクあたり4.5〜10 µs、LuaJCは70〜110 µsだった。
- **メタスペース**：3000チャンクで16 MB増えた。関数ごとにJVMのクラスが1つ作られるため。
- **依存関係**：BCEL 5.2（Apache License 2.0、約520 KB）が必要になる。

## 見つかったLuaJCの問題

| 問題 | 影響 | 状態 |
| --- | --- | --- |
| `ProtoInfo.substituteVariable` が、同じ置換を命令の数だけ繰り返していた（解析がO(n³)） | 2000行のファイルのコンパイルが終わらず、ランチャーが固まる | 修正済み（sidemenu.lua：6470 → 43 ms） |
| upvalueの解析で、後からの取り込みが先の `UpvalInfo` の変数を奪い、読み取り専用か書き換え可能かの判定が食い違う | `NoSuchFieldError: u0`（ModernChicの選曲スキンが読み込めない） | 修正済み（514ファイル中、型が食い違うファイルが2 → 0） |
| 初期化されていないレジスタへのアクセス | `VerifyError`（Dozer_result、forループの中のクロージャ） | 未修正。`loadVerified` で検出してインタプリタに切り替える |
| メインチャンクが64 KBを超える | `ClassFormatError`（WMII_FHDのresultMain.lua） | 未修正。インタプリタに切り替える |
| コード生成時のNPE | SocialSkinの4ファイル、goto.lua | 未修正。インタプリタに切り替える |
| **`if`/`elseif` で値を入れ、クロージャから書き換えるローカル変数の入れ物が、クロージャ間で共有されない** | **エラーを出さずに誤った値を返す**（メニューを開閉しても表示が変わらない） | **未修正。上流の3.0.2からある問題で、検出もできない** |

最後の問題は、sidemenu.luaと同じ構造の再現コードで確認した。メニューの状態を切り替えたあとの各クロージャの値は次のとおり。
インタプリタは `01111111111010001`、LuaJCは `01000000000010001` になる。

この結果は、上流3.0.2、現行jar、修正前のmasterのいずれでも同じだった。upvalueをすべて書き換え可能として扱わせても直らない。
原因は判定ではなく、入れ物（cell）の割り当て方にある。

## 互換性（DebugLib無しで81スクリプトを実行し、インタプリタと比較）

45本は出力が一致した。違いは次のとおり。
- エラーメッセージにファイル名と行番号が付かない
- 数値の `for` の引数が文字列だと失敗する
- `xpcall` の1ケースでハンドラが呼ばれない
- コンパイル済みの関数に `string.dump` を使えない
- `tostring(function)` の表示が変わる
- DebugLibの振る舞いが異なる

## 再開する場合

1. upvalueを「ローカル変数1つにつき入れ物を1つ割り当て、それを全クロージャで共有する」方式に作り直す。
2. スキンのすべての関数を、インタプリタとLuaJCの両方で実行して結果を比べる差分テストを用意し、採用の判定に使う。
3. 上記の修正パッチと `loadVerified`（実行前の検証と、インタプリタへの切り替え）は、そのまま使える。
